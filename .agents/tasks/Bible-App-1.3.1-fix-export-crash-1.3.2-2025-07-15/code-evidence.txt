=== STEP 2: ROOT CAUSE ===

The 1.3.1 font fix block ran synchronously at module level, before app.whenReady().
GTK then initialised inside app.whenReady() and cached its fontconfig state from the
already-modified fonts.conf. When the user clicked Export, renderInHiddenWindow()
created a second BrowserWindow with { sandbox: true }. This triggered fontconfig 2.12.6
(from gnome-3-28-1804 runtime) to re-read fonts.conf and try to rebuild its cache.
If $XDG_CACHE_HOME/fontconfig did not exist, or if fontconfig's internal state was stale
from the pre-GTK-init modification, this caused SIGABRT/SIGSEGV.

=== STEP 3: FIX APPLIED ===

Option A+B was applied to src/main/main.ts:
  A) Moved entire font fix block from module level into app.whenReady(), placed after
     setAppMenu() and before createWindow().
  B) Added mkdirSync call to ensure $XDG_CACHE_HOME/fontconfig exists before
     fs.writeFileSync writes the corrected fonts.conf.
  - Added import os from 'os'; for homedir() fallback in cacheDir construction.
  - GTK_IM_MODULE block at module level: UNCHANGED (byte-for-byte identical to base).
  - studyExport.ts: NOT modified.
